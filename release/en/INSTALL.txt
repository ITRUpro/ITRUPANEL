ITRUPANEL 0.1.92 — INSTALLATION AND UPDATES

Requires a clean Linux VPS or dedicated server, root access, systemd and internet.
Supported: Debian 11–13, Ubuntu 22.04/24.04/26.04, AlmaLinux and Rocky Linux 8–10,
CentOS Stream 9–10 and RHEL 8–10.
Supported architectures: amd64 and arm64. Shared hosting is not supported.

Run as root (no sudo):
wget -O install.sh https://itrupanel.com/panel/install-itrupanel.sh && bash install.sh

The installer downloads the full release and verifies its SHA-256 checksum.
Save the administrator credentials printed at completion.
Open https://SERVER_IP:3333 in your browser.
The initial certificate is self-signed. Configure your domain and a trusted
certificate in Server information → Panel address and SSL.

If the panel is installed, this command updates it and backs up the program
and affected settings. From version 0.1.16 you can also click Updates in the
top right corner. Updates contain all previous fixes and missed migrations.
The release signature and archive checksum are checked before installation.
From version 0.1.19, the panel first prepares the release while showing transfer
progress. Click “Restart panel and apply” when ready; until then the current
version keeps running. Preparation expires after 24 hours without applying.
Closing the tab does not approve installation. After you click Apply, an
independent systemd service continues installation even if the tab closes.
After restart, sign in and open Updates to view the result. The dialog does not open automatically. This workflow applies
to subsequent updates FROM 0.1.19. Root terminal updates still apply immediately.
Back up sites, databases and mail separately; update backups do not replace them.

NEW INSTALLATION STATISTICS (since 0.1.24)
After a successful fresh installation, the installer sends a random ID and version to https://itrupanel.com/install-stats/api.php. The server stores the connection IP address (the server's public IP) and estimates the country from it locally; statistics are stored encrypted. No domains, credentials or configuration are sent. Reporting is optional and network failure does not affect installation. Disable before installation: ITRUPANEL_INSTALL_STATS=0 bash install.sh. Updates and duplicate IDs do not increase the count. Earlier installations are not counted retroactively. Cloned installations retain their original ID. On every update check (while the panel is open, at most every 15 minutes) the panel sends the same random ID and version; panels installed before statistics create an ID on their first check. To disable on an installed panel: touch /usr/local/itrupanel/etc/installation-stat-disabled

SITE PROTECTION (0.1.37)
Open Site protection and configure each website. Start with Monitor, then enable Block mode. Configure real_ip from trusted proxies before enabling limits behind a CDN. This does not replace upstream DDoS protection or protect the separate admin port. Custom return/rewrite directives and nested includes require review; explicit conflicting limits and access_log directives are rejected. Logs: /var/log/itrupanel-security/DOMAIN.log, daily rotation, 7 archives, maxsize 20M checked when logrotate runs.

LOGIN PROTECTION (since 0.1.38)
Panel: 5 failed attempts per IP within 10 minutes block new logins for 15 minutes.
Enabled automatically. Blocks persist in var/login-guard.json across restarts.
Existing sessions can view and remove blocks under Login protection.
Behind a shared reverse proxy, the proxy address shares the limit.
FTP: choose Install and enable, then enter the Pure-FTPd port (usually 21).
Requires Linux with systemd and fail2ban, nftables, python3-systemd from OS repositories.
No third-party repositories are added. Initial setup may restart FTP.
Check: fail2ban-client status itrupanel-ftp
Only the selected FTP port is blocked; local server connections are excluded.
Dedicated nftables table: inet itrupanel_f2b. Other jails are not restarted.
If login state cannot be saved, new logins fail closed. Fix disk/permissions first.
Emergency root recovery removes all panel blocks:
  systemctl stop itrupanel
  mv /usr/local/itrupanel/var/login-guard.json /usr/local/itrupanel/var/login-guard.json.backup
  systemctl start itrupanel
